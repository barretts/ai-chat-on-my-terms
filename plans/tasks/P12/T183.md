# T183 — Auto-heal marker: never re-attempt a model-specific native JSON-grammar crash

[Phase index](../../phases/P12.md) · [Execution rules](../../03-execution.md) · [Contracts](../../02-contracts.md)

**Start after:** T179 row-3 device runs (root cause captured). Owner-approved approach
2026-10-21: "auto-heal marker" — a native crash cannot be caught (SIGABRT kills the process
before any JS runs; llama.rn ships the crashing code as a prebuilt `rnllama.xcframework` with
no patchable source), so the catch lives ACROSS the process boundary: a durable marker written
BEFORE each native JSON attempt tells the next launch which model the grammar killed.

**Root cause (proven, [device evidence](../../../implementation/evidence/parity/t179/README.md)):**
requesting `response_format: {type:"json_object"}` (`modules/gguf/ios/src/index.ts:253`) makes
llama.rn's worker thread call `common_sampler_init` (grammar build); for the HauhauCS Qwen3.5
2B Aggressive vocabulary that throws a C++ exception with no handler → `std::terminate` →
SIGABRT. Five `.ips` logs identical; crashes land within ~1 s of the first topic-interest
selector after a clean checkpoint. Same llama.cpp failure class as ggml-org/llama.cpp#21571,
#23775, #23990, but llama.rn surfaces it as process abort instead of request error. Tinman
Gemma 4 E4B completes identical grammar calls — the bug is per-model vocabulary/template, NOT
our grammar string, NOT memory (no jetsam frames in any log).

**Behavior contract**
1. Marker BEFORE the call, cleared on clean finish. `grammarProbe` record keyed by
   `sha256(modelUri + llama.rn version)` — write it when a `json:true` run STARTS; delete when
   that run reaches a terminal event (`finishReason`/error/cancel) without the process dying.
   A leftover marker at next launch means: that model's last JSON attempt killed the app.
2. Launch-time decision: marker present → the model is `grammarQuarantined` (session-persistent
   + durable set): every subsequent run for it omits `response_format` (plain-text selector
   through the existing parse pipeline — the group driver's selector consumer already tolerates
   unstructured replies via the seating-order fallback) and the bench/manifest notes say
   `"json mode quarantined for <modelId> after native grammar crash"`. The model NEVER
   requests grammar again until the quarantine is lifted (new model file blob = new key;
   llama.rn version bump = new key).
3. Honest first-crash cost: the first JSON attempt for an unseen model can still die. That
   death is now self-recording — after restart the bench offers the checkpoint Share AND the
   UI states plainly what happened ("topic selection crashed natively for <model>; retrying in
   text mode"). No silent degradation: quarantine status appears in manifests + a Settings-line
   note with a "re-enable JSON mode" reset per model (owner opt-in, default stays quarantined).
4. Scope guard: `modules/gguf/ios` owns marker + quarantine so ALL GGUF consumers (group chat,
   bench, solo chat json features) inherit it; `json:false` runs never write markers.
5. Upstream: file a llama.rn issue attaching `crash-0351-selector.ips` (stack + repro model id
   `blob:01a15b4d-d661-7466-bcf7-139c173a8b7f` + iOS 26.6 / iPhone 17 Pro Max). Link it in the
   module doc comment. Revisit a native try/catch ONLY if upstream ships a source-buildable fix.

**Implementation notes (verified at `b99ae28`)**
- Injection point: `createGgufInferencePort` call chain in `apps/mobile/platform/local-chat-provider.ts:12`
  — wrap `inference.startRun` in a decorator here (keeps `modules/gguf/ios` pure), or accept an
  optional `grammarGuard` port in `createGgufInferencePort({files, grammarGuard})`
  (`modules/gguf/ios/src/index.ts:75 startRun`) — prefer the decorator: zero module API churn.
- Marker storage: `File`/`Paths.document/locallab/grammar-probe/<key>.json` (precedent
  `platform/model-download.ts`); quarantine list beside it (`grammar-quarantine/<key>.json`).
  Sync `File.exists`/read at session start; async write on start; tolerate corrupt files = no
  marker (fail-open on read, fail-CLOSED on write: if the marker cannot be written, skip the
  JSON request and note it — never risk an unrecorded crash).
- Key must include llama.rn version (`node_modules/llama.rn/package.json` = `0.12.4`, import
  via a constant + test pin) AND the resolved staged model file identity: `request.modelId` is
  already the managed `blob:` id; file re-download mints a new blob id, so modelId+version is
  sufficient — do NOT hash file bytes on every run (12 GB file class).
- Crash-adjacent state to reuse: bench `sweepStaleBenchSessions` + checkpoint self-heal
  (`apps/mobile/features/group-bench/runner.ts`) already prove the restart-detect pattern.
- Tests (web, vitest in `modules/gguf/ios/test/` + bench tests): decorator writes marker on
  start & deletes on terminal event; marker present at init → startRun drops `json` from
  params and stamps `notes`; quarantine survives simulated restart (fs stub persists); reset
  clears; `json:false` never touches markers; two models independent.
