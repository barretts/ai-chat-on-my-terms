# T052 — Memory extraction and management

Date: 2026-09-26. Feature IDs: **ME-01, ME-02, ME-03, ER-08**.

## Implemented

- `packages/memory/extraction`: injected `ProviderMemoryExtractor`, bounded serial background orchestration, strict candidate JSON, exact user-message provenance and source quotes, deterministic duplicate suppression, SQLite CRUD, prompt resolution, local consent preferences, persistent UUIDv7/HLC identity and sync revision/tombstone journals.
- Eligibility reads the durable completed run and original user message. Canceled, failed, running, empty visible replies and oversized turns do not trigger extraction. Only visible `text` parts enter generation; reasoning, tools, sources and attachment/log parts are excluded. Consent and completed status are rechecked before an atomic commit. Regeneration uses its original user-message identity.
- The extractor invokes the actual injected generation `ProviderPort`, with the selected provider/model identity and adapter-owned credentials. Generation failure, invalid/unsupported candidates or cancellation add no facts. There is no heuristic extraction fallback. Candidate facts must quote eligible user text; recognizable credential values are rejected.
- Durable cancellation is separate from actual resources draining. The extractor tracks the pending iterator read and `return()` cleanup; the coordinator retains raw operation/drain promises and blocks another background run until cleanup finishes. Foreground admission waits up to five seconds, then raises `MemoryResourcesBusyError` while retaining the occupied gate. Suspension can cancel durable work promptly without claiming resources are released. Deleted entries stay out of provider extraction input while local tombstones prevent recreation.
- `apps/mobile/features/memory`: native Data / Memory screen with extraction and injection toggles, searchable paginated facts, manual add, edit, delete and validated source-message links. Persona/conversation scopes are retained. Unknown old namespaces remain excluded from prompts and have explicit review/adoption and deletion controls.
- `memory_items` remains the compatible projection. Versioned metadata stores the frozen `MemoryEntrySchema` provenance/scope/revision and local source descriptor. Every create/edit/delete records its frozen entity/tombstone in the same transaction. Sync imports preserve identity/revision, reject privacy-scope mutation, and give equal-revision tombstones precedence. Older updates cannot resurrect an unknown deleted identity.
- `MEMORY_EXTRACTION_SCHEMA_SQL` adds the content-key index, revision log, extraction claims, local preferences and persisted HLC clock. Coordinator registration with the shared migration allocator is separate from this owned module.

## Integration contract

The coordinator supplies the shared SQLite port and selected provider binding, resolves conversation/Persona consent into `MemoryPolicy`, mounts `MemoryScreen`, prepends `promptContext` to future prompts, and enqueues after a completed terminal event. It must recheck consent through `isStillAllowed(transaction)`, passing the scoped port into storage reads; cancel background extraction and pass bounded resource admission before a foreground local-model send; use cancellation without waiting for resources during suspension; and await actual drainage/disposal before database closure. Shared database transactions must be serialized across feature owners. Package README documents the public API and bounds.
