**Implementation steps**
1. Implement an iPhone ProviderPort adapter for the Responses API at the official OpenAI endpoint, with a user-editable HTTPS Responses endpoint URL (default https://api.openai.com/v1/responses) and user-configurable model ID.
2. Use SecretStore references for a user-supplied API key, never bundle a project key, resolve the secret only for the chosen connection, send Bearer authorization only to the validated endpoint, reject cross-origin redirects and redact request/error logging.
3. Parse streamed Responses SSE text deltas and terminal/error events into ordered RunEvents, propagate cancellation, and map unauthorized, offline, missing-model and malformed-response failures into typed recoverable errors.
4. Provide a compact native endpoint setup and model selection surface that T158 can mount without depending on full provider settings or account/onboarding flows.

**Functional smoke check**
- [ ] A Responses-compatible fixture streams text, completes and cancels through ProviderPort; API key bytes never appear in fixtures, transcripts, logs or exports.
- [ ] Native endpoint URL, model ID and secure key reference persist across relaunch; the adapter receives only the secret resolved for the selected host.
