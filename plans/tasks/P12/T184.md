# T184 — Shipped starter character pack: trope personas + bundled avatars

[Phase index](../../phases/P12.md) · [Execution rules](../../03-execution.md) · [Contracts](../../02-contracts.md) · [Coverage](../../05-coverage.md)

**Start after:** nothing hard; land after T183 (both touch persona-adjacent boot paths) and
in the same build as it so build 28 gives the owner tropes AND the crash fix at once.

**Feature IDs:** PE-01 (named character + avatar + prompt), PE-04 (seeded-once semantics —
generalized from the single Mini assistant to a pack). NEW coverage row proposed:
`PE-11 | Shipped starter trope pack with avatars, re-loadable | T184 | iPhone T184 | T159B`
(coverage owner to add).

**Why ship one:** a fresh install today has exactly two personas (empty "Default" + one
generic assistant), so first-run group chats (the product's centerpiece, T170-T180) start
degenerate and T179 row-6 avatar device testing requires the owner to hand-pick photos.
Distinct, ready-made characters make onboarding instantly demoable and give the persona
library real content day one.

**Content contract (legal — non-negotiable)**
- Tropes are ideas; implementations are OURS. NEVER copy names, bios, or prompts from
  character-card sites (chub/character card imports are provenance-poisoned) or trademarked
  characters (no "Sherlock", "Yoda", "Deadpool", Wodehouse names). Original names, original
  prose, drafted in-repo.
**Trope lineup (14 = core 8 + anime 6; names final-draftable by implementer, keep the
archetype spread; anime names are original given-name choices, never franchise characters)**

Rationale: fourteen clashing registers = good group-chat dynamics AND a sharper parroting
probe (verbatim echo stands out against distinct voices; each prompt includes
"stay in your own voice; never repeat another participant's phrasing" — mitigation, not the
parroting fix, which stays its own card). The anime six are exactly the persona styles people
actually build for group roleplay, and they stress-test voice separation hardest. Yandere and
ecchi/catgirl flavors deliberately EXCLUDED: SFW line (store builds) + the obsessive-love
trope reads as harassment in multi-persona rooms.

**Ground truth (verified at `231a613`)**
- Seed-once + tombstone pattern to generalize: `SQLitePersonaLibrary.initialize`
  (`packages/personas/library/src/index.ts:226-248`) — state marker `seed.locallab-assistant.v1`,
  `persona_tombstones` + direct-row check prevent resurrection after user deletes; fixed id
  `STARTER_PERSONA_ID` :17. Library `insert(db, id, draft, isDefault, isStarter)` supports
  fixed ids + `PersonaDraft.photoAttachmentId` (`:206`).
- Avatar storage path already exists and is the ONLY path: persona avatars are managed
  **attachments** (`apps/mobile/features/personas/avatar.ts` — pick→attachment→`photoAttachmentId`,
  ≤8 MB, jpeg/png/webp/heic); programmatic ingest: `ingestAttachment`
  (`packages/attachments/src/index.ts:146`). Seeded personas attach avatars the same way;
  NO new avatar storage.
- Appearance fallback exists: `PersonaAppearance` accent/background colors + shape
  (`packages/personas/library/src/index.ts:21-30`) — initials/tint render when no photo;
  avatar ingest failure must leave persona usable (no photo, colored initials).
- Persona list + create UI: `apps/mobile/features/personas/screen.tsx`; persona owner ids
  are EntityIds (`avatar.ts` validateOwnerId default).
- Bench personas stay hardcoded (control set for T179 parity numbers) — DO NOT replace them.

**Implementation steps**
1. `packages/personas/starter-pack/` (new workspace pkg, pure): `tropes.ts` (the 8 records:
   fixed v7 UUIDs `0195c000-…0010`-`0017`, name/description/prompt, chosen accent/background
   colors), `seed.ts` with `seedTropePack(db, deps)` — mirrors Mini pattern: state marker
   `seed.tropes.v1` installs-all-once; per-persona tombstone check so individually deleted
   tropes stay deleted across launches; returns inserted ids.
2. Avatars: 8 own-generated 512×512 PNGs at
   `apps/mobile/assets/starter-personas/<key>.png` (≤ ~40 KB each, flat background matching
   the persona's accent color), each with a `<key>.prompt.md` provenance sidecar (icon
   precedent). Regenerate-in-place allowed until acceptance.
3. Composition-layer boot (`apps/mobile/composition/` persona-library construction site):
   after `SQLitePersonaLibrary.initialize`, run `seedTropePack` with an avatar dep
   `attach(personaId, assetKey)`: read bundled asset → `ingestAttachment` → set
   `photoAttachmentId` (post-insert update or draft field — whichever the insert path
   cleanly supports; do NOT fork storage). Avatar ingest failure = persona kept, no photo,
   `console` note; persona insert failure for one trope must not abort the pack.
4. "Load character pack" affordance on the persona screen (header menu + list empty state):
   re-inserts any missing trope, CLEARS its tombstone when the user explicitly asks; avatar
   attach best-effort as above.
5. `plans/05-coverage.md`: add the PE-11 row above.
6. Tests (`packages/personas/starter-pack/test/`, vitest like `library.test.ts` in-memory):
   installs all 8 once; second init inserts 0; deleted-tome deleted-trope stays deleted
   across "restart"; explicit reload resurrects + retombstones cleanly; avatar dep failure →
   personas present photo-less; fixed ids stable across reload.

**Check level:** Feature. Package tests web-green; `@locallab/mobile` typecheck green;
device proof (T179-style, filed under `docs/implementation/evidence/parity/t184/` if needed
by row 6): fresh install shows 8 tropes WITH avatars; group room of {Aldric, Sunny, Bingham}
renders each seat's avatar + keeps voices distinct for ≥1 dice round; delete Sunny → reinstall
does NOT resurrect; "Load character pack" brings her back.

**Acceptance**

   zero photo-picker trips.
2. Group setup can form a room from tropes in <3 taps; avatars show in seats + history.
3. Deletion semantics match Mini (PE-04 generalized); explicit reload works.
4. Web tests + typecheck green; no new native pods (assets only → CNG-clean).
5. Ledger row + `plans/05-coverage.md` PE-11 row in the same commit chain.
