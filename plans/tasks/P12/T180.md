**Implementation steps**
1. Gate: `EXPO_PUBLIC_DEV_BENCH === "1"` read at runtime; set `"1"` in `eas.json` preview env only; extend the `app.config.js` store guard to flag any `EXPO_PUBLIC_DEV_*` var.
2. `apps/mobile/features/group-bench/matrix.ts` (pure): fixed 5 bench personas (distinct name+prompt for personality/repetition notes), fixed userText kickoff, matrix = installed model ids × {2,3,5} seats × {round-robin, dice, topic-interest}, deterministic dice seeds, per-scenario conversation/room ids.
3. `apps/mobile/features/group-bench/core.ts` (pure ports, testable): `BenchPorts` (allocate, save/load room, makeBinding with recording port, driver startTurn per round, runtime release, thermal/memory probe, cleanup SQL, personas+prompts); per scenario: seed room draft → save/load → R rounds (first `send` with kickoff, rest `pass`), accumulate presenter entries as history, slice run-records per round (selector `json:true` runs tagged separately), capture `frozenOrder` + round status; release + cleanup after each scenario so 4B unloads between scenarios.
4. Recording port decorator: wraps `ProviderPort.startRun`, keys records by `request.messageId`, captures wall-clock start/end, `Usage` tokens, finish reason; yields events untouched.
5. `apps/mobile/features/group-bench/runner.ts` (RN glue, mirrors route bootstrap verbatim): builds real ports; manifest JSON `{version, device, iosVersion, appVersion, buildNumber, generatedAt, roundsPerScenario, responseLimitTokens, thermalBefore/After, scenarios:[{modelId, seats, policy, diceSeed, roomId, conversationId, rounds:[{trigger, status, frozenOrder, durationMs, replies:[{persona, displayName, replyMessageId, durationMs, inputTokens, outputTokens, tokensPerSec, text}]}]}]}`; writes `locallab/bench/group-bench-<stamp>.json` via `File`/`Paths`, shares via `expo-sharing`, copies via `expo-clipboard`.
6. `apps/mobile/features/group-bench/section.tsx` + mount in `features/chat-settings/screen.tsx` next to `AnalyticsSection` (`:655-662`), gated: model multiselect (installed GGUFs), seats/policies fixed by matrix, rounds 1-5, response limit 64/128/256, Run/Stop, progress line `scenario i/N`, Share + Copy buttons; unmount cancels.
7. Tests `apps/mobile/features/group-bench/bench.test.mts` (vitest, wired into `test:group-features`): matrix shape (models×3×3, fixed dice seeds, distinct persona prompts), recording port event pass-through + usage capture, core flow vs fake ports (round slicing, selector-run tagging, frozenOrder recorded, release+cleanup per scenario, Stop mid-scenario yields partial manifest), manifest JSON round-trip.
8. Ship build 25 (buildNumber bump) after commit; T179 row 3 then runs from the button and ingests the manifest into `docs/implementation/evidence/parity/t179/`.
