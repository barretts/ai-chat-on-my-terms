# Persona and memory native composition

Date: 2026-09-26. Local Windows implementation evidence; physical iPhone and live-model proof are pending.

- `/chat` mounts Persona library/profile and Data Memory surfaces against the same SQLite connection as the chat engine.
- A shared database adapter serializes every read, write and transaction and takes `BEGIN IMMEDIATE` before each feature transaction. Transaction callbacks receive a scoped connection; issued statements drain before commit or rollback, and escaped/nested scopes are rejected. Independent writes wait for another feature's rollback and then survive it. Blob/archive helpers bind to the existing transaction without opening a nested one.
- Chat reads a Persona snapshot before send, uses that exact prompt for the request, then saves the same identity under the allocated run ID. Avatar blobs receive durable `persona-run:<runId>` ownership. Switching Persona preserves transcript rows; profile edits affect the next run.
- Persona parameter presets participate in settings resolution. Preferred provider/model/voice/workflow bindings and historical transcript appearance remain later integration work.
- Extraction and injection default to off. Default Persona uses opt-in global facts; custom Personas use isolated private facts. Explicit associations/sharing and individual Persona toggles remain T053.
- Completed-turn extraction uses the selected real ProviderPort/model/connection, a bounded background queue and grounded JSON validation. Durable user/assistant message identities preserve correct regeneration provenance. Foreground send/provider changes wait for actual pending iterator and cleanup work, with a five-second actionable busy error that preserves the occupied gate. Suspension and disabling extraction cancel durable work promptly; disposal waits for actual resources before database closure. Deleted facts stay out of provider requests while local tombstones suppress recreation. Consent and eligibility rechecks use the transaction-scoped connection.
- Foreground admission captures the suspension epoch. A background transition invalidates an unfinished preflight even if the app returns before dispatch; suspension during asynchronous handle allocation stops the resulting handle before its stream can run. The AppState listener directly stops an active handle while lifecycle persistence catches up.
- Memory links reopen and highlight the exact original user message. Management edits and deletions preserve the source conversation.
- Versions4–7 register Persona, memory, Arena and tool-engine tables. Mobile initializes the shared versioned embedded migration runner before any feature store. Generated SQL matches registered source files; prior unversioned core adoption requires compatible table/constraint/index/FK metadata, and mismatch is rejected without stamping a version.
