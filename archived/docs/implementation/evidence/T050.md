# T050 - Persona library, profiles, and seed rules

Date: 2026-09-26. Features: PE-01, PE-03, PE-04, PE-05, PE-10.

## Implementation

- `packages/personas/library` publishes `PersonaLibraryPort` and its concrete
  `SQLitePersonaLibrary`. Names, descriptions, system prompts, managed photo references,
  appearance, timestamps, UUIDv7 identity, and HLC revisions survive database reopen.
- `PERSONA_LIBRARY_SQL` adds profile metadata, durable seed state, deletion tombstones,
  conversation selection, and immutable run snapshots. Existing optional `personas`
  rows are preserved and their metadata is backfilled after the optional schema exists.
  The coordinator owns versioned migration registration.
- Default is protected from deletion. The project-owned **LocalLab assistant** is
  installed once; its independent deletion marker and tombstone prevent restoration
  even if an upgrade retries seed installation. Reopening never overwrites edits.
- Selection changes only `conversation_personas`; it never clears or rewrites messages,
  runs, or conversation timestamps. Captured runs retain their original profile after
  edits, switches, or deletion. `snapshotForNextRun` supplies the next response's prompt.
  `captureRun(conversationId, runId, preSendSnapshot)` supports engines that allocate
  run identity internally and records exactly the profile used at provider start.
- Individual-chat and add-to-group intents carry stable Persona identity and a frozen
  profile snapshot. Creating the conversation and dispatching group work remain the
  composition root's responsibility.
- `PersonaScreen` provides library/profile views, create/edit/delete, name, description,
  system prompt, avatar selection/removal, accent/background colors, avatar shape,
  individual chat, group launch, and switching in the current chat. Default has no delete
  control; rejected stale edits produce a safe recovery message. Native primitives have
  explicit accessibility labels.
- `createManagedPersonaAvatarPort` wraps the app's actual native image intake. It accepts
  bounded supported image types and private managed file previews, releases rejected picks,
  and rejects remote URLs or file hosts. Canceling editing releases staged image references;
  committed edits remain committed if unused-image cleanup must retry on exit.
- Additional profile JSON is bounded and validated; credential fields are rejected.
  Raw errors, prompts, and credentials are absent from this evidence artifact.
- Mutation callbacks use the explicit SQLite transaction facade for all reads and writes.
  Legacy adapters that call the callback without a facade remain supported.
