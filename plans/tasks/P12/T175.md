**Implementation steps**
1. Route `app/group-chat.tsx?roomId=…`: loads the saved room (`SQLiteGroupConfigStore.loadRoom`), ensures its dedicated group conversation (T170), builds the room runtime (T174) and turn driver (T172/T173).
2. Turn controller bar: **Send** (composer text, one user message, everyone one turn, then wait for user), **Pass** (disabled before conversation start), **Ask** per participant (composer text optional), **Stop** (cancel current generation; later seats never start). Disable Send/Pass/Ask while any is running (engine guard from T172 enforces server-side too).
3. Presentation: `Complete replies` (default) buffers each participant's stream and reveals the message only when its run completes; while waiting show speaker-status line ("Maya is thinking…") with the current participant's avatar/initial. `Live text` streams incrementally; on stop the partial is marked interrupted. Completed replies publish individually — no waiting for the whole round.
4. Reopen semantics: opening a room mid-round shows completed replies + a disabled-input notice with **Start a new round** — never auto-resumes generation.
5. Keep existing group speech playback ("Play replies in order") working on completed messages only; update the placeholder copy at :79 (it ships with real scheduling now).
