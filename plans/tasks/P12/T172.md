**Implementation steps**
1. `ChatEngine.beginAssistantRun({conversationId, participantId, modelId, parameters, preparedContext?, systemPrompt?})`: inserts NO user message; creates an assistant `messages` row with `participant_id` set and a `runs` row; returns the same `ChatRunHandle` streaming contract used by `send()`. The durable write path (`writeProjection`) must persist assistant text to that message; cancellation keeps the run+partial message exactly like solo interruption.
2. `AdvancedChatEngine` variant accepting a fully prepared message list (already-built group transcript context) plus attribution, bypassing `buildContext()`'s conversation SELECT but reusing `packContext` token budgeting with the current user/group instruction message marked required.
3. Persist `participant_id` on ALL engine inserts where supplied (solo path passes nothing — behavior unchanged). Projection (`packages/chat-projection`) must surface it so later cards render speaker names.
4. Round writer in `packages/groups/config`: `beginRound(roomId, {trigger: "send"|"pass"|"ask", frozenOrder, settingsSnapshot})` → `group_rounds`; `beginSpeakerRun(roundId, seatIndex, personaId, modelId)` / `completeSpeakerRun(runId, status)` → `group_runs`; statuses `pending|running|completed|failed|interrupted`.
5. Single-action guard at the engine seam: while a group round holds the guard, `send()` for that conversation and any second round trigger are rejected (actionable error, no queue-of-rounds). Stop sets an abort flag the sequential loop checks between seats.
