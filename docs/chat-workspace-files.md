# Chat files

Each conversation has a durable workspace for Markdown (`.md`) and plain text (`.txt`) files. Files survive app restarts and remain until the chat is permanently deleted. Deleting a chat removes its workspace and tool invocation records in the same database transaction.

Ask directly, for example `Write notes/plan.md with a three-step plan`, or enable **Write files** to save the next complete response as `notes.md`. The chat menu's **Files** screen supports creating/editing files, Markdown preview, original source, clipboard copying, exporting an individual file and exporting the folder structure as ZIP. On iPhone, export opens the system share sheet, where Save to Files is available. The browser downloads files. Exports do not execute code.

The all-chats ZIP backup also includes workspace files. Import restores them under the imported chat IDs, preserving file contents and revisions. Chat-only JSON and Markdown exports remain transcript exports; use ZIP to back up the files.

For a verified NInfer connection, the model receives native `workspace_list_files`, `workspace_read_file` and `workspace_write_file` functions when the request concerns files. Reads are paged at 16,384 Unicode characters by default (maximum 32,768), with total size and a continuation offset. Writes return the actual saved path, size and revision. A requested file is confirmed only after a successful write. Other models can create a document through a complete-response fallback: the app adds a document instruction before context packing and saves only a completed, uncanceled response. Truncated output or a missing completion event is not saved. The fallback does not support model-driven listing or reading; users can open Files directly.

NInfer requests explicitly follow the app's **Reasoning** setting. With Reasoning off, the server receives `enable_thinking: false`; this avoids consuming the response budget on hidden thinking before the document or tool call. Other compatible servers do not receive this NInfer extension. The default response allowance is 2,048 tokens for file requests and 4,096 with Reasoning on; an explicit **Maximum output tokens** setting takes priority.

The local NInfer XML parser and chat-template changes are recorded in [the server patch](../patches/ninfer-workspace-tool-parser.patch). String parameters use quoted JSON and escape `<` as `\u003c`; argument replay and tool results use the same safe encoding. JSON decoding restores the original text, including XML tags, whitespace and newlines. The server accepts legacy raw text too, but literal parameter-closing tags require quoted JSON. Focused parser, frontend and API schema checks passed. Two real-model runs with Reasoning off and a 2,048-token response allowance saved/read exact Markdown, Unicode, XML, code fences and final newlines; the second also preserved all three literal tool-closing tags.

Files are UTF-8 text in SQLite, scoped to a conversation rather than native filesystem paths. Relative nested paths preserve folder structure. Absolute paths, parent traversal, reserved device names and unsupported extensions are rejected. Limits are 256 KiB per file, 128 files and 8 MiB per chat. Replacing a file requires its current revision, preventing stale model/manual edits from silently overwriting newer content. Tool argument, result, deadline and context budgets are also bounded; a model cannot run commands through this workspace.

Local checks cover real SQLite restart/deletion behavior, revision conflicts and rollback, Unicode paging, complete/incomplete fallback output, actual ZIP byte integrity, provider function-call streaming/replay and phone-width browser controls. These checks do not establish a physical iPhone run.
